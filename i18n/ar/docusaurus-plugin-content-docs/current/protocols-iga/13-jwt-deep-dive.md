# تعمق في JWT - JWS و JWE وخوارزميات التوقيع و JWK

## بنية JWT

رمز الويب JSON (JWT) هو وسيلة مكثفة وآمنة لتمثيل المطالبات بين طرفين. يتكون من ثلاثة أجزاء: الرأس والحمولة والتوقيع، مفصولة بنقاط.

```
eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6IkpvaG4gRG9lIiwiaWF0IjoxNTE2MjM5MDIyfQ.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c
```

### الرأس

```json
{
  "alg": "RS256",
  "typ": "JWT",
  "kid": "key-2026-09"
}
```

- `alg`: خوارزمية التوقيع (مثل `RS256`, `ES256`, `EdDSA`).
- `typ`: نوع الرمز (`JWT`).
- `kid`: معرف المفتاح، يستخدم لاختيار مفتاح التوقيع من JWKS.

### الحمولة

```json
{
  "sub": "1234567890",
  "name": "John Doe",
  "iat": 1516239022,
  "exp": 1516242622,
  "iss": "https://idp.example.com",
  "aud": "https://api.example.com"
}
```

المطالبات القياسية:
- `sub`: الموضوع (معرف المستخدم).
- `iss`: المصدر (مزوّد الهوية).
- `aud`: الجمهور (المستلم المقصود).
- `exp`: وقت الانتهاء.
- `iat`: وقت الإصدار.
- `nbf`: وقت عدم الصلاحية قبله.
- `jti`: معرف JWT (معرف فريد لمنع إعادة التشغيل).

### التوقيع

يتم حساب التوقيع فوق الرأس والحمولة المشفرة بـ base64url:

```
HMACSHA256(
  base64UrlEncode(header) + "." + base64UrlEncode(payload),
  secret
)
```

التوقيع يضمن عدم العبث بالرمز بعد الإصدار.

## JWS: توقيع الويب JSON

JWS هو المتغير الموقّع من JWT. يستخدم مفاتيح غير متماثلة أو متماثلة لتوقيع الرمز.

### التسلسل المكثف لـ JWS

التسلسل المكثف هو التنسيق ثلاثي الأجزاء المفصول بالنقاط الموضح أعلاه. وهو التنسيق الأكثر شيوعًا لـ JWTs في OIDC و OAuth 2.0.

### التسلسل JSON لـ JWS

التسلسل JSON هو كائن JSON يمكن أن يحتوي على توقيعات متعددة:

```json
{
  "payload": "eyJzdWIiOiIxMjM0NTY3ODkwIn0",
  "signatures": [
    {
      "protected": "eyJhbGciOiJSUzI1NiJ9",
      "header": {"kid": "key-1"},
      "signature": "Signature1"
    },
    {
      "protected": "eyJhbGciOiJFUzI1NiJ9",
      "header": {"kid": "key-2"},
      "signature": "Signature2"
    }
  ]
}
```

التسلسل JSON نادرًا ما يُستخدم في الممارسة؛ التسلسل المكثف هو المعيار.

## JWE: تشفير الويب JSON

JWE هو المتغير المشفر من JWT. يوفر السرية لمحتويات الرمز.

### التسلسل المكثف لـ JWE

JWE له خمسة أجزاء، مفصولة بنقاط:

```
BASE64URL(UTF8(JWE Protected Header)) || '.' ||
BASE64URL(JWE Encrypted Key) || '.' ||
BASE64URL(JWE Initialization Vector) || '.' ||
BASE64URL(JWE Ciphertext) || '.' ||
BASE64URL(JWE Authentication Tag)
```

### عملية تشفير JWE

1. ولّد مفتاح تشفير المحتوى (CEK) للتشفير المتماثل (مثل AES-256-GCM).
2. اشفر الحمولة بـ CEK.
3. اشفر CEK بالمفتاح العام للمستلم (مثل RSA-OAEP أو ECDH-ES).
4. كوّن JWE من CEK المشفر و IV والنص المشفر وعلامة المصادقة.

### متى تستخدم JWE

- الرمز يحتوي على بيانات حساسة يجب تشفيرها (مثل PII، البيانات الصحية).
- الرمز يمر عبر وسطاء غير موثوقين (مثل بوابات API، طوابير الرسائل).
- المتطلبات التنظيمية تفرض تشفير البيانات الشخصية أثناء النقل.

## خوارزميات التوقيع

### RS256 (RSASSA-PKCS1-v1_5 مع SHA-256)

- غير متماثل: يوقّع بمفتاح RSA خاص، يتحقق بمفتاح RSA عام.
- مدعوم على نطاق واسع، ناضج، ومفهوم جيدًا.
- حجم المفتاح: 2048 بت كحد أدنى (3072 بت موصى به للأمان طويل الأمد).
- الأداء: أبطأ من خوارزميات المنحنى الإهليلجي.

### ES256 (ECDSA مع P-256 و SHA-256)

- غير متماثل: يوقّع بمفتاح ECDSA خاص، يتحقق بمفتاح ECDSA عام.
- مفاتيح أصغر من RSA (256 بت مقابل 2048 بت) لأمان مكافئ.
- أسرع من RSA للتوقيع والتحقق.
- يتطلب تنفيذًا دقيقًا لتجنب هجمات إعادة استخدام nonce.

### EdDSA (Ed25519)

- غير متماثل: يوقّع بمفتاح Ed25519 خاص، يتحقق بمفتاح Ed25519 عام.
- سريع، آمن، ومقاوم لهجمات القناة الجانبية.
- حتمي: لا يتطلب nonce، مما يقضي على مخاطر إعادة استخدام nonce.
- دعم متزايد في المكتبات الحديثة.

### HS256 (HMAC مع SHA-256)

- متماثل: يوقّع ويتحقق بنفس السر المشترك.
- سريع وبسيط، لكن يتطلب توزيع مفاتيح آمن.
- مناسب للرموز الداخلية حيث المصدر والمحقق هما نفس النظام.
- غير مناسب للرموز التي تعبر حدود الثقة.

### مقارنة الخوارزميات

| الخوارزمية | النوع | حجم المفتاح | السرعة | حالة الاستخدام |
|---|---|---|---|---|
| RS256 | غير متماثل | 2048 بت | معتدل | أغراض عامة، دعم واسع |
| ES256 | غير متماثل | 256 بت | سريع | تطبيقات حديثة، مفاتيح أصغر |
| EdDSA | غير متماثل | 255 بت | الأسرع | تطبيقات حديثة، حرجة أمنيًا |
| HS256 | متماثل | 256 بت | الأسرع | رموز داخلية، نفس نطاق الثقة |

### هجمات الخلط بين الخوارزميات

يحدث هجوم الخلط بين الخوارزميات عندما يغير المهاجم رأس `alg` من خوارزمية غير متماثلة (مثل `RS256`) إلى خوارزمية متماثلة (مثل `HS256`)، ويستخدم المحقق المفتاح العام كسر HMAC.

الدفاع:
- ارفض الرموز ذات قيم `alg` التي لا تتطابق مع الخوارزمية المتوقعة.
- استخدم مكتبة تتحقق من الخوارزمية مقابل قائمة بيضاء.
- لا تستخدم نفس المفتاح لكل من الخوارزميات غير المتماثلة والمتماثلة.

## JWK و JWKS

### JWK (مفتاح الويب JSON)

JWK هو كائن JSON يمثل مفتاحًا تشفيريًا:

```json
{
  "kty": "RSA",
  "kid": "key-2026-09",
  "use": "sig",
  "alg": "RS256",
  "n": "0vx7agoebGcQSuuPiLJXZptN9nndrQmbXEps2aiAFbWhM78LhWx4cbbfAAtVT86zwu1RK7aPFFxuhDR1L6tSoc_BJECPebWKRXjBZCiFV4n3oknjhMstn64tZ_2W-5JsGY4Hc5n9yBXArwl93lqt7_RN5w6Cf0h4QyQ5v-65YGjQR0_FDW2QvzqY368QQMicAtaSqzs8KJZgnYb9c7d0zgdAZHzu6qMQvRL5hajrn1n91CbOpbISD08qNLyrdkt-bFTWhAI4vMQFh6WeZu0fM4lFd2NcRwr3XPksINHaQ-G_xBniIqbw0Ls1jF44-csFCur-kEgU8awapJzKnqDKgw",
  "e": "AQAB"
}
```

حقول المفتاح:
- `kty`: نوع المفتاح (`RSA`, `EC`, `oct`, `OKP`).
- `kid`: معرف المفتاح، يستخدم لاختيار المفتاح من JWKS.
- `use`: استخدام المفتاح (`sig` للتوقيع، `enc` للتشفير).
- `alg`: الخوارزمية المقصود للمفتاح.
- `n` و `e`: معامل RSA والأس (لمفاتيح RSA).

### JWKS (مجموعة مفاتيح الويب JSON)

JWKS هو كائن JSON يحتوي على مصفوفة من JWKs:

```json
{
  "keys": [
    {
      "kty": "RSA",
      "kid": "key-2026-09",
      "use": "sig",
      "alg": "RS256",
      "n": "0vx7agoebGcQSuuPiLJXZptN9nndrQmbXEps2aiAFbWhM78LhWx4cbbfAAtVT86zwu1RK7aPFFxuhDR1L6tSoc_BJECPebWKRXjBZCiFV4n3oknjhMstn64tZ_2W-5JsGY4Hc5n9yBXArwl93lqt7_RN5w6Cf0h4QyQ5v-65YGjQR0_FDW2QvzqY368QQMicAtaSqzs8KJZgnYb9c7d0zgdAZHzu6qMQvRL5hajrn1n91CbOpbISD08qNLyrdkt-bFTWhAI4vMQFh6WeZu0fM4lFd2NcRwr3XPksINHaQ-G_xBniIqbw0Ls1jF44-csFCur-kEgU8awapJzKnqDKgw",
      "e": "AQAB"
    },
    {
      "kty": "RSA",
      "kid": "key-2026-08",
      "use": "sig",
      "alg": "RS256",
      "n": "...",
      "e": "AQAB"
    }
  ]
}
```

مزوّد الهوية ينشر JWKS الخاص به عند نقطة نهاية قياسية (مثل `/.well-known/jwks.json`). المحقق يجلب JWKS، يختار المفتاح بـ `kid`، ويستخدمه للتحقق من توقيع الرمز.

### تدوير المفاتيح

تدوير المفاتيح هو عملية استبدال مفاتيح التوقيع دوريًا. مزوّد الهوية ينشر مفاتيح متعددة في JWKS خلال فترة الانتقال:

1. مزوّد الهوية يولّد زوج مفاتيح جديد ويضيفه إلى JWKS بـ `kid` جديد.
2. مزوّد الهوية يوقّع الرموز الجديدة بالمفتاح الجديد.
3. المحقق يجلب JWKS المحدثة ويمكنه التحقق من الرموز الموقعة بأي من المفتاحين.
4. بعد انتهاء صلاحية جميع الرموز الموقعة بالمفتاح القديم، مزوّد الهوية يزيل المفتاح القديم من JWKS.

## ربط الرمز

ربط الرمز يربط الرمز باتصال TLS محدد، مما يمنع سرقة الرمز وإعادة التشغيل.

### DPoP (إثبات الحيازة)

DPoP (RFC 9449) يربط الرمز بمفتاح خاص للعميل. العميل يولّد زوج مفاتيح، يضم المفتاح العام في طلب الرمز، ويوقّع كل طلب بالمفتاح الخاص. الخادم يتحقق من التوقيع لإثبات أن العميل يمتلك المفتاح الخاص.

```http
GET /resource HTTP/1.1
Authorization: DPoP eyJhbGciOiJFUzI1NiIsInR5cCI6ImRwb3Arand0IiwidHlwIjoiZHBvcCtqd3QifQ.eyJzdWIiOiIxMjM0NTY3ODkwIiwiaWF0IjoxNTE2MjM5MDIyfQ.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c
DPoP: eyJhbGciOiJFUzI1NiIsInR5cCI6ImRwb3Arand0IiwidHlwIjoiZHBvcCtqd3QifQ.eyJqdGkiOiJ1dWlkLTEyMzQ1Njc4OTAiLCJodG0iOiJHRVQiLCJodHIiOiJodHRwczovL2FwaS5leGFtcGxlLmNvbSIsImlhdCI6MTUxNjIzOTAyMn0.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c
```

### ربط الرمز بـ mTLS

ربط الرمز بـ mTLS (RFC 8705) يربط الرمز بشهادة TLS للعميل. العميل يقدم الشهادة أثناء مصافحة TLS، والخادم يربط الرمز ببصمة الشهادة.

## هجمات JWT الشائعة

### هجوم الخوارزمية none

المهاجم يزيل التوقيع بتعيين `alg` إلى `none` وإزالة جزء التوقيع. يجب على المحقق رفض الرموز ذات `alg=none`.

### هجوم الخلط بين المفاتيح

كما موضح أعلاه، المهاجم يغير `alg` من `RS256` إلى `HS256` ويوقّع الرمز بالمفتاح العام كسر HMAC.

### هجوم السر الضعيف

إذا تم استخدام `HS256` بسر ضعيف، يمكن للمهاجم كسر السر بالقوة الغاشمة وتزوير الرموز. استخدم سرًا عشوائيًا قويًا (256 بت كحد أدنى).

### هجوم الرمز المنتهي

المهاجم يعيد تشغيل رمز منتهي. يجب على المحقق التحقق من مطالبة `exp` ورفض الرموز المنتهية.

### هجوم خلط الجمهور

المهاجم يستخدم رمزًا صدر لجمهور واحد للوصول إلى جمهور مختلف. يجب على المحقق التحقق من مطالبة `aud` ورفض الرموز ذات الجمهور غير المتوقع.

### هجوم خلط المصدر

المهاجم يستخدم رمزًا صدر من مزوّد هوية مختلف. يجب على المحقق التحقق من مطالبة `iss` ورفض الرموز من مصادر غير متوقعة.

## قائمة التحقق

- [ ] فهم بنية JWT (الرأس، الحمولة، التوقيع).
- [ ] فهم الفروق بين JWS و JWE.
- [ ] اختيار خوارزمية التوقيع بناءً على حالة الاستخدام.
- [ ] تكوين نقطة نهاية JWKS لتوزيع المفاتيح.
- [ ] تنفيذ عملية تدوير المفاتيح.
- [ ] النظر في ربط الرمز (DPoP أو mTLS) للسيناريوهات عالية الأمان.
- [ ] الدفاع ضد هجمات JWT الشائعة.

## ما تعلمه هذه الصفحة

- JWT هو تنسيق رمز مكثف: الرأس والحمولة والتوقيع، مفصولة بنقاط.
- JWS يوفر السلامة (التوقيع)؛ JWE يوفر السرية (التشفير).
- اختيار خوارزمية التوقيع يعتمد على حالة الاستخدام: RS256 للتوافق، ES256 للتطبيقات الحديثة، EdDSA للتطبيقات الحرجة أمنيًا.
- JWKS هي آلية توزيع المفاتيح: مزوّد الهوية ينشر المفاتيح، والمحقق يختار بـ `kid`.
- تدوير المفاتيح ضروري: انشر مفاتيح متعددة أثناء الانتقال، أزل المفاتيح القديمة بعد الانتهاء.
- ربط الرمز يمنع سرقة الرمز: DPoP يربط بمفتاح خاص، mTLS يربط بشهادة.
- هجمات JWT حقيقية: تحقق من الخوارزمة والجمهور والمصدر والانتهاء.
